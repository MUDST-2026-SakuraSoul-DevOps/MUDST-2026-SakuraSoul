# แผนงานฝั่ง frontend

บันทึกไว้ให้คนทำ frontend สองคนแบ่งงานกันได้โดยไม่ต้องมานั่งคุยใหม่ทุกรอบ
และให้คนที่มารับช่วงต่ออ่านแล้วรู้ว่าอะไรเสร็จแล้ว อะไรยังค้าง เพราะอะไร

อัปเดตล่าสุด 5 ก.ย. 2569

## สถานะตอนนี้

งานของ Natthanan เสร็จแล้วทั้ง 5 ใบ แยกเป็น 5 สาขาซ้อนกันเป็นชั้น
แต่ละสาขาต่อจากสาขาก่อนหน้า ไม่ได้แตกจาก `frontend` ทุกอัน เพราะทั้งห้า story
ใช้ชั้น API กองเดียวกัน ถ้าแตกจาก `frontend` ตรง ๆ สาขาหลังจะไม่มีไฟล์นั้นแล้ว build ไม่ผ่าน

ตอนเปิด PR ต้องเลือก base ให้ตรงกับสาขาก่อนหน้า ไม่ใช่ `frontend` ทุกอัน
มีแต่ PR แรกเท่านั้นที่ base เป็น `frontend` พอ PR แรก merge แล้ว GitHub จะเลื่อน base
ของ PR ถัดไปให้เอง merge เรียงตามลำดับในตาราง

**SSK-24 ต่อปุ่มเข้าหน้าจอเรียบร้อยแล้ว** ตัวสร้างไฟล์กับปุ่ม `ExportLogButton` เสร็จและมีเทส
ครบทั้งสาม scenario และปุ่มถูกวางไว้บนหัวแท็บ Maintenance Log ของ `MaintenancePage.tsx`
แล้ว โดยรับรายการ **ที่กรองแล้ว** เข้าไป ไม่ใช่ทั้งหมด ตามที่ US-18-S2 ระบุว่าไฟล์ต้องมี
เฉพาะรายการที่ตรงกับตัวกรองที่ผู้ใช้เลือกไว้ ถ้าจะแก้แท็บนั้นต่อ ต้องรักษาข้อนี้ไว้

```tsx
<ExportLogButton tickets={filtered} />
```

**US-16-S3 เรื่อง snapshot อัตราในใบเสร็จ ทำที่ฝั่งนี้ไม่ได้** ใบเสร็จเป็นของ SSK-16
ข้อกำหนดคือใบเสร็จต้องเก็บอัตราที่ใช้ตอนออกใบไว้ในตัวมันเอง ห้ามอ้างกลับมาที่ตาราง config
ไม่งั้นพอแอดมินเปลี่ยนอัตรา ใบเสร็จเก่าทุกใบจะเปลี่ยนยอดตาม ซึ่งผิดทั้งทางบัญชีและกฎหมาย
เขียนไว้ใน `docs/api-contract-lease.md` ให้คนทำ SSK-16 แล้ว ส่วนฟอร์มตั้งอัตราบอกผู้ใช้
ไว้ชัดว่าอัตราใหม่มีผลกับใบเสร็จที่ออกหลังจากนี้เท่านั้น

ยังทำไม่ได้ในรอบนี้ ไม่ใช่เพราะลืม แต่เพราะต้องรอของอื่นก่อน

- **US-05-S2 race condition** ต้องพิสูจน์ด้วย integration test ฝั่ง backend ที่ยิงสองคำขอพร้อมกัน
  ฝั่งหน้าเว็บกับ backend จำลองเป็น single thread ทั้งคู่ ทดสอบข้อนี้แทนไม่ได้ อยู่ใน SSK-26
- **ต่อ backend จริง** ตาราง `lease` ยังไม่มี หน้าเว็บจึงรันบน backend จำลองอยู่
  ดูสัญญาที่ตกลงกันไว้ใน [api-contract-lease.md](api-contract-lease.md)

## แบ่งงานยังไงให้ไม่ชนกัน

กฎเดียวที่ต้องจำ **หนึ่งคนหนึ่งหน้า ต่อหนึ่งสาขา** ไฟล์ที่ใช้ร่วมกัน
(`src/components/`, `src/api/`, `src/domain/`) ถ้าจะแก้ให้บอกอีกคนก่อน
เพราะสองคนแก้ไฟล์เดียวกันคนละสาขาคือที่มาของ conflict เกือบทั้งหมดในโปรเจกต์ขนาดนี้

ถ้าต้องเพิ่ม component กลางจริง ๆ ให้แยกเป็น PR เล็ก ๆ ของตัวเองแล้ว merge ก่อน
ค่อยแตกสาขาหน้าจอออกมาจาก `frontend` ที่มีของนั้นแล้ว

## คิวงานถัดไป

เรียงตามที่ควรทำก่อนหลัง ตัวเลขในวงเล็บคือ Jira issue

### รอบก่อน 12 ก.ย.

1. **รีวิวและ merge ทั้ง 5 สาขาตามลำดับในตารางข้างบน**
   ต้องมีคนในทีมอย่างน้อยหนึ่งคน approve ตามกฎใน README และ CI ต้องเขียวทุกใบ
2. **ป็อปอัปเพิ่มผู้เช่า** (SSK-9 / US-03)
   ตอนนี้ฟอร์มเพิ่มผู้เช่าเป็นแผงที่กางออกมาใต้หัวข้อ ดีไซน์ใน Figma เป็นป็อปอัป
   (node 378:1960) เอา `src/components/Modal.tsx` ที่มีอยู่แล้วไปใช้ได้เลย งานไม่หนัก
   ชุดฟิลด์เปลี่ยนไปแล้วตามโน้ตของอาจารย์ (11 ก.ย. 2569) เพิ่ม Line ID เข้ามาและอีเมล
   ไม่บังคับอีกต่อไป ฝั่ง backend ทำตามนั้นแล้ว ของที่ต้องตามแก้อยู่ในบั๊ก SSK-99
   ซึ่งกินแปดไฟล์ ไม่ใช่แค่ตัวป็อปอัป คือ `src/api/types.ts`, `src/domain/tenant.ts`,
   `src/domain/tenant.test.ts`, `src/dialogs/AddTenantDialog.tsx`,
   `src/dialogs/AddTenantDialog.test.tsx`, `src/pages/TenantsPage.tsx`,
   `src/api/mockApi.ts` และ `src/api/client.test.ts` (ยังไม่มีเคสสร้างผู้เช่าเลย)
   รายละเอียดว่าแต่ละไฟล์ต้องแก้อะไรกับข้อความไทยทุกประโยคอยู่ในหัวข้อ
   "ข้อมูลผู้เช่า ฟิลด์ติดต่อ (US-03)" ของ [api-contract-lease.md](api-contract-lease.md)
3. **ป็อปอัปเพิ่ม/แก้ห้อง** (SSK-22 / US-16 บางส่วน)
   Figma มี Add Unit (node 378:2143) กับ Edit Unit (node 397:1344)
   ต้องรอ `POST` กับ `PUT /api/rooms` จากฝั่ง backend ก่อนจึงจะบันทึกได้จริง
   ถ้ายังไม่มี ให้ทำ UI กับเทสไว้ก่อนแล้วต่อ API ทีหลัง

### รอบก่อน 26 ก.ย.

4. **หน้า Login** (SSK-7, SSK-8 / US-01, US-02)
   **ได้คำตอบแล้ว ลงมือได้เลย** ฝั่ง backend (SSK-28) เลือก **session cookie ไม่ใช่ token**
   แปลว่าหน้าเว็บไม่ต้องเก็บอะไรลง `localStorage` ไม่ต้องแนบ header เอง เบราว์เซอร์
   ส่ง cookie ให้เองทุกคำขอเพราะอยู่ origin เดียวกัน
   endpoint ทั้งสามตัวกับข้อความ error ทุกอันอยู่ใน
   [api-contract-lease.md](api-contract-lease.md) หัวข้อ "การเข้าสู่ระบบ (US-01, US-02)"
   สองอย่างที่ต้องทำนอกจากตัวหน้าจอคือ ดัก 401 ไว้ที่ `client.ts` ที่เดียวแล้วพาไป `/login`
   และเรียก `GET /api/auth/me` ตอนเปิดแอปเพื่อตัดสินว่าจะเข้าหน้าไหน
5. **ต่อ backend จริงแทน backend จำลอง**
   พอ `V4__lease.sql` กับ endpoint ขึ้นแล้ว ตั้ง `VITE_API_MOCK=0` ใน `.env.development`
   แล้วรัน `npm run test` ถ้า `src/api/client.test.ts` ยังผ่าน แปลว่าสองฝั่งตรงกัน
   ถ้าไม่ผ่าน อ่าน diff แล้วคุยกับคนทำ backend ว่าใครหลุดจากสัญญา
6. **หน้า Payments** (SSK-16 / US-10) ต้องรอ endpoint ใบเสร็จจาก CR-04

### รอบก่อน 17 ต.ค.

7. **หน้า Maintenance** (SSK-18 ถึง SSK-21)
   **ไม่ต้องรออะไรแล้ว ลงมือได้เลย** `V8__maintenance.sql` กับ endpoint ฝั่ง backend ขึ้นครบแล้ว
   ทั้งใบแจ้งซ่อม ประวัติรายห้อง คลังอุปกรณ์ และการแจ้งเตือนตามรอบ
   รูปร่างข้อมูล ข้อความ error ทุกประโยค และตารางเทียบป้ายสถานะบนหน้าจอ
   (`Wait for Assign` / `Pending` / `In Progress`) กับค่า `OPEN` / `IN_PROGRESS` / `DONE`
   อยู่ใน [api-contract-maintenance.md](api-contract-maintenance.md) หัวข้อ "สิ่งที่หน้าเว็บต้องเปลี่ยน"
   ซึ่งไล่ไว้เป็นตารางแล้วว่าแต่ละแท็บต้องยิง endpoint ไหนแทน `useState` ตัวไหน
   สามแท็บที่ยังเหลือคือ Maintenance Tasks, Supplies & Inventory และ Reminders
   ส่วนแท็บ Maintenance Log ยิง `GET /api/maintenance` ผ่าน `fetchMaintenanceLog` อยู่แล้ว
   ป้ายเตือนบนการ์ดห้องได้ค่าจริงมาแล้วโดยหน้าเว็บไม่ต้องแก้อะไร (`openMaintenanceCount`
   กับ `openMaintenanceTitle` รูปร่างเดิม) และ `fetchRoomMaintenance` กับ
   `fetchMaintenanceLog` เลิกต้องทน 404 ได้แล้ว (404 ของ `/api/rooms/{id}/maintenance`
   แปลว่าไม่พบห้อง ไม่ใช่ยังไม่มี endpoint)
8. **หน้า Appliances** (SSK-23 / US-17) `AppliancesPage.tsx` ที่มีอยู่เป็นเฟรม
   "Appliance Rental" ของ Figma คือรายการขอเช่าของพร้อมค่าเช่าและสถานะ
   Active / Pending / Returned ซึ่ง **ยังไม่มี endpoint ฝั่ง backend เลยสักตัว**
   ส่วน `/api/supplies` ที่พร้อมแล้วเป็นของคลังอุปกรณ์ซ่อม ซึ่งอยู่ในแท็บ
   Supplies & Inventory ของ `MaintenancePage.tsx` ไม่ใช่หน้านี้ ต้องเคลียร์กับเจ้าของ
   requirement ก่อนว่าหน้านี้จะเอาแบบไหน ดูหัวข้อ "ของที่ยังไม่ได้ตกลง" ของสัญญา API
9. **E2E ด้วย Playwright** (SSK-26) เริ่มจากเส้นทางเดียวก่อน
   เช็คอินห้องว่าง แล้วเช็คเอาต์ ผ่านหน้าเว็บจริง

## หน้าที่ยังเป็นโครงเปล่า รอเจ้าของ ticket มาทำต่อ

สามหน้านี้ยังใช้ค่าคงที่ที่ก๊อปมาจาก Figma อย่าเผลอคิดว่าเป็นข้อมูลจริงตอนเดโม
แต่เหตุผลที่ยังไม่ได้ต่อ API ไม่เหมือนกันแล้ว

| ไฟล์ | เป็นของ ticket | ทำไมยังเป็นค่าคงที่ |
| --- | --- | --- |
| `src/pages/PaymentsPage.tsx` | SSK-16 ออกใบเสร็จ | endpoint ใบเสร็จยังไม่มี |
| `src/pages/MaintenancePage.tsx` | SSK-18 ถึง SSK-21 งานซ่อมบำรุง | endpoint มีครบแล้ว เหลือสามแท็บที่ยังไม่ได้ต่อ (แท็บ Maintenance Log ต่อแล้ว) |
| `src/pages/AppliancesPage.tsx` | ยังไม่มีเจ้าของ | เป็นเฟรม Appliance Rental ซึ่งยังไม่มีใครนิยาม และไม่มี endpoint เลย ส่วนคลังอุปกรณ์ของ SSK-23 อยู่ในแท็บ Supplies & Inventory ของหน้า Maintenance |

สามหน้านี้ติดมากับสาขาแรกเพราะเมนู sidebar ในดีไซน์มีเจ็ดเมนู ถ้าไม่มีไฟล์พวกนี้
router จะพังทั้งแอปจนเปิดหน้า Dashboard ไม่ได้ ไม่ได้ตั้งใจไปทำงานของคนอื่น
เจ้าของ ticket เขียนทับไฟล์ของตัวเองได้เลย ไม่ต้องเกรงใจ

## เช็คก่อนเปิด PR ทุกครั้ง

```bash
cd frontend
npm run lint
npm run test
npm run build
```

สามคำสั่งนี้คือสิ่งเดียวกับที่ `ci.yml` รันบน GitHub ถ้าผ่านที่เครื่องแล้วยังแดงบน CI
ให้สงสัยเรื่องเวอร์ชัน Node ก่อนเป็นอย่างแรก
