## เตรียมเครื่องก่อนขึ้นเวที (ทำทีเดียว ล่วงหน้า 30 นาที)

```bash
# 1. ตั้งรหัส (ครั้งเดียว) คัดลอก .env.example เป็น .env แล้วใส่ค่าที่สุ่มเอง
cp .env.example .env

# 2. ยกทั้ง stack พร้อมชุด observability
docker compose -f docker-compose.yml -f docker-compose.observability.yml up -d --build

# 3. ทดลองยิงทราฟฟิกสักรอบดูว่าทุกกราฟขยับ
ADMIN_PASSWORD='<รหัสเดียวกับ APP_ADMIN_PASSWORD ใน .env>' observability/demo/traffic.sh --rounds 5 --pay
```

ตอนขึ้นเวทีรัน `observability/demo/traffic.sh` ค้างไว้ใน terminal (ไม่ใส่ `--pay`) กราฟจะไม่นิ่ง
แล้วค่อยรันอีกหน้าต่างด้วย `--pay` ตอนถึงนาทีที่ 7:00 เพื่อให้ตัวเลขเงินขยับให้เห็นสด ๆ

ข้อมูลตัวอย่าง: ถ้าฐานข้อมูลว่าง dashboard Business จะเป็นศูนย์ทั้งหมด ให้สร้างสัญญากับใบเสร็จผ่านหน้าเว็บก่อน
อย่างน้อย 3 ห้อง ที่มีทั้งใบจ่ายแล้วและใบค้าง (มีใบเกินกำหนดอย่างน้อยหนึ่งใบ) จะเห็นทุกช่องมีค่า

## คำถามที่น่าจะโดน

- **ทำไม business metric เป็น gauge จากฐานข้อมูล ไม่ใช่ counter** backend มีสอง pod และรีสตาร์ตได้ ตัวนับในหน่วยความจำจะเพี้ยน ค่าจากฐานข้อมูลตรงกันทุก pod
- **เก็บข้อมูลส่วนบุคคลใน metric/log/trace ไหม** metric เป็นผลรวมล้วน span ไม่ใส่อีเมล ชื่อ หรือค่าพารามิเตอร์ SQL (ไลบรารีแทนเป็น `?`)
- **ทำไม `/actuator/prometheus` ไม่เปิดสู่สาธารณะ** ต้องใช้ HTTP Basic ของผู้ใช้ `metrics` และ nginx คืน 404 ให้ path นี้ มีเทสพิสูจน์ (`MetricsEndpointSecurityTest`)
- **เก็บข้อมูลนานแค่ไหน** Prometheus 3 วัน, Loki และ Tempo 72 ชั่วโมง เพื่อไม่ให้กิน disk ของ runner
- **Phase 2 หลายอาคารทำให้ metric เปลี่ยนไหม** ต้องเพิ่ม label `building` ใน `BusinessMetrics` กับ dashboard Business (บันทึกไว้ใน `observability/README.md`)
- **ถ้า trace ทำให้ช้า** เก็บทุกคำขอ (sampling 1.0) เพราะทราฟฟิกหอพักน้อย ลดได้ด้วย `TRACING_SAMPLING_PROBABILITY`

## ต้องเตรียมก่อนวันพรีเซนต์ (ทีมต้องทำ/ตัดสินใจ)

1. **อัดวิดีโอซ้อมสำรอง 3 นาที** ของข้อ 5 ตอนทุกอย่างทำงานดี เก็บไว้ในเครื่องเวทีและ USB
2. **แคปภาพหน้าจอ** Actions ที่เขียว, Contributors, trace ใน Tempo, dashboard ทั้ง 4 ตัว
3. **ซ้อมจับเวลาอย่างน้อย 2 รอบ** ทั้งชุด 10 นาที ข้อไหนเกินให้ตัดตามตาราง "ถ้าเวลาเกิน"
4. **ข้อ 3 GitHub runner** ปัจจุบัน workflow ทั้งหมดรันบน runner ที่ GitHub ให้ (`ubuntu-latest`) ยังไม่มี self-hosted runner
   (README ระบุว่ายังไม่ได้ทำ) ทีมต้องตัดสินใจว่าจะพูดตามความจริงนี้ หรือตั้ง self-hosted runner ให้เสร็จก่อนวันพรีเซนต์
5. **Grafana บน k8s ในรันเนอร์ดูสดไม่ได้** cluster ใน CI ถูกทิ้งเมื่อ job จบ จึงเดโมสดด้วย `docker compose` บนเครื่องเวที
   แล้วอ้างผลของ `deploy.yml` ว่าตรวจชุดเดียวกันบน k8s จริง (ถ้าอยากเดโมบน k8s สดต้องยก minikube บนเครื่องเวทีเองและใช้ `minikube service grafana -n sakura-soul --url`)
6. **ข้อมูลตัวอย่าง** เตรียมฐานข้อมูลที่มีสัญญาและใบเสร็จครบแบบข้างบน ไม่ใช้ข้อมูลผู้เช่าจริง
7. **รหัสผ่านบนจอ** อย่าเปิดไฟล์ `.env` ขณะแชร์หน้าจอ
